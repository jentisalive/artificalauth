# artificalauth

**ArtificalAuth 0.1.3-beta** — авторизация ArtificalSMP через Telegram и нативные Java-диалоги, целиком на Velocity + LimboAPI. Отдельный Paper-плагин авторизации не требуется.

## Возможности

- Регистрация привязкой Minecraft-ника к Telegram.
- Подтверждение входа через Telegram либо вход по выданному паролю, если подтверждение отключено.
- Запоминание входа с одного IP на настраиваемый срок.
- Управление через бота: завершение игровой сессии, восстановление пароля, отвязка с блокировкой ника, настройка подтверждения входа.
- Ограничение попыток ввода, временная блокировка IP, сроки действия кодов и кнопок.
- Хеширование паролей PBKDF2-HMAC-SHA256 с индивидуальной солью.
- Консольные команды перезагрузки настроек и освобождения заблокированного ника.
- Закрытый вход при неготовности плагина; нет автоматического сброса повреждённой базы аккаунтов.

Отдельный Bedrock-интерфейс обсуждается, но **в версии 0.1.3-beta ещё не реализован**.

## Установка

1. Нужны совместимые Velocity и LimboAPI. Текущая реализация диалогов привязана к Java Minecraft **1.21.11, protocol 774** и внутренним классам Velocity; совместимость с другими версиями не гарантируется.
2. При остановленном прокси поместить актуальный ArtificalAuth и `limboapi-1.1.27-SNAPSHOT.jar` из `dist/` в `plugins/`. Не устанавливать несколько версий ArtificalAuth одновременно.
3. Скопировать шаблон `src/main/resources/config.yml` в `plugins/artificalauth/config.yml` либо дать плагину создать его при первом запуске.
4. Настроить `bot.username`, токен и `routing.target-server`, затем включить `enabled: true`.
5. Токен рекомендуется передавать через переменную окружения `ARTIFICAL_AUTH_BOT_TOKEN`, а не хранить в публикуемом конфиге.
6. Проверить регистрацию, подтверждение Telegram и вход по паролю на тестовом сервере.

Пока настройки не заполнены, плагин намеренно закрывает вход. Backend должен быть недоступен в обход прокси, а modern forwarding — настроен независимо от плагина.

Команды по умолчанию:

```text
/auth                    — повторно открыть окно авторизации
authadmin reload         — перечитать конфиг, только консоль Velocity
authadmin unlock <ник>   — освободить заблокированный ник, только консоль
```

Имена команд можно изменить в конфиге. `unlock` не подтверждает владение аккаунтом: после освобождения ника возможна новая регистрация, поэтому применять его следует только после проверки администрацией.

## Сборка и тесты

`build.ps1` компилирует Java-код с `--release 21`, упаковывает SnakeYAML и запускает `AuthTests`. Нужен JDK с `javac` и API jar совместимого Velocity, LimboAPI и SnakeYAML.

Пример с явными путями:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 `
  -JavaHome "C:\Java\jdk-25" `
  -VelocityJar "C:\Minecraft\Velocity\server.jar" `
  -SnakeYamlJar "C:\Minecraft\Main\libraries\org\yaml\snakeyaml\2.2\snakeyaml-2.2.jar"
```

Путь к `lib/limboapi.jar` определяется относительно проекта. Результат — `dist/ArtificalAuth-0.1.3-beta.jar`.

`integration/run.py` содержит интеграционный тест с локальным Telegram API и клиентом протокола 774. Он написан для исходного стенда ArtificalSMP: пути, стартовый шаблон Velocity и тестовый сервер необходимо подготовить отдельно. Папка работающего тестового сервера в Git не включена.

Исторические `install-0.1.2.ps1` / `install-0.1.3.ps1` также используют исходные абсолютные пути. Не запускать их на другом сервере без проверки.

## Содержимое

| Путь | Назначение |
| --- | --- |
| `src/main/` | Актуальный код ArtificalAuth и безопасный шаблон конфига |
| `src/test/` | Тесты движка и диалогов |
| `dist/` | Собранные версии плагина, шаблон настроек, зависимость LimboAPI |
| `lib/` | LimboAPI для компиляции и метаданные происхождения |
| `integration/` | Код интеграционного теста и описание протокола |
| `backups/` | Архивные исходники, сборки и заметки; рабочие конфиги/аккаунты исключены |
| `DialogAuth/`, `RealDA/` | Сторонние исходники из локальной папки, с исходными README и лицензиями; не требуются для запуска ArtificalAuth |

Сведения о сторонних компонентах: [THIRD_PARTY.md](THIRD_PARTY.md).

## Безопасность публикации

В репозиторий не включены Telegram-токены, базы аккаунтов, forwarding secrets, рабочие конфиги из установочных бэкапов, журналы, IDE-файлы, результаты компиляции и полные тестовые серверы. Содержимое `src/main/resources/config.yml` и `dist/config.yml` — шаблоны, не боевые настройки.
