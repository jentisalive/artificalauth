# ArtificalAuth 0.1.4-beta — native Bedrock UI

21.10.2026. Предыдущая версия: 0.1.3-beta.

## Изменения

- `BedrockUi` отделяет необязательный интерфейс от классов Geyser/Cumulus: Java-only установка не обязана содержать эти API.
- `BedrockForms` создаёт Cumulus SimpleForm для register/telegram и CustomForm с предупреждением и полем пароля для password.
- `GeyserForms` использует прямой Geyser API на этом же Velocity. Определение Bedrock учитывает Geyser и, при наличии, Floodgate; префикс ника не используется.
- Ответы форм передаются в ограниченную очередь состояния ArtificalAuth, затем проверяются объект клиента, nonce, этап, срок авторизации и признак уже разрешённого входа.
- Каждый показ формы имеет свою генерацию. Ответ на старый показ, повторный callback и callback программного закрытия не меняют состояние.
- Отложенная отправка и ограниченные повторы отменяются по смене поколения/сеанса. При недоступности формы вход не разрешается.
- Успешная авторизация, кик и реальный выход закрывают принадлежащую клиенту форму. Старый объект клиента не закрывает форму нового подключения с тем же UUID.
- Native Bedrock-путь не отправляет Java DialogClear и не обрабатывает Java CustomClickAction. Java-путь сохраняет protocol 774.
- Формы не получают URL-действие «открыть Telegram»: такая возможность не гарантируется стандартной SimpleForm. Код и имя бота показаны в тексте.
- Пароли не вводятся через игровую команду и не включаются в диагностический `toString()` ответа.

## Конфигурация

Новые значения шаблона `src/main/resources/config.yml`:

```yaml
bedrock:
  enabled: true
  send-delay-ms: 500
  retry-delay-ms: 500
  max-send-attempts: 5
```

Добавлены сообщения `bedrock-password-warning`, `bedrock-password-placeholder`, `bedrock-form-closed`, `bedrock-form-unavailable`.
Существующий загрузчик объединяет недостающие настройки со встроенным шаблоном только в памяти. Рабочий `config.yml`, токен и `accounts.json` не перезаписываются. `bedrock.enabled: false` оставляет прежние Java-диалоги/их перевод Geyser, а не отключает авторизацию.
Выбор интерфейса фиксируется при входе в Limbo: изменение `bedrock.enabled` через reload применяется к новым подключениям; уже ожидающий игрок сохраняет свой интерфейс.

## Сборка

`build.ps1` собирает отдельный `dist/ArtificalAuth-0.1.4-beta.jar`, не перезаписывая старые jar.
Параметры `-GeyserJar` и `-FloodgateJar` добавляют API в classpath компилятора; эти зависимости не встраиваются в плагин. На Java-only сервере они необязательны в runtime.
Каждая сборка использует новый каталог классов, чтобы не включить устаревшие классы из предыдущей версии.

## Проверки

- `AuthTests`: логика Telegram, хранилище, ограничения входа, формат Java-диалогов и общий guard ответов.
- `BedrockFormsTests`: настоящие Cumulus codecs из установленного Geyser, разбор ответов, интерфейс всех трёх этапов, пароль после label, ошибки, закрытие/замена, повторные и устаревшие ответы, очередь, ограниченные повторы, старый конфиг без перезаписи и сквозной сценарий форм через настоящий Engine.
- `integration/run.py`: изолированный Velocity + LimboAPI, локальный имитатор Telegram, Java-клиент 1.21.11; `--with-geyser` дополнительно устанавливает Geyser/Floodgate и проверяет сохранение Java-пути рядом с ними.
- `integration/test-install.ps1`: установка 0.1.3 → 0.1.4 в отдельный каталог, резервная копия и побайтовое сохранение конфига/аккаунтов. Рабочий сервер не переключается.

Проверки выполнены: 72 проверки `AuthTests`, 55 проверок `BedrockFormsTests`, интеграционный Java-сценарий без Geyser и с Geyser/Floodgate, изолированная установка. Тестовый дочерний процесс получает только фиктивный Telegram-токен, даже если у администратора задан боевой токен в окружении.

Unit-транспорт форм имитируется, а не выдаётся за настоящий Bedrock-клиент. Доставку и визуальное поведение на телефоне/консоли, переключение приложений и работу формы внутри Limbo нужно проверить реальным Bedrock-подключением. Успешное принятие формы Geyser API не доказывает, что она уже отрисована клиентом.

## Обновление

Остановить Velocity, сделать резервную копию `plugins/artificalauth/`, заменить старый jar на 0.1.4-beta, запустить прокси обычным способом. Не оставлять два ArtificalAuth одновременно и не использовать PlugMan/reload для замены кода.
`install-0.1.4.ps1` без параметров показывает план; `-Apply` выполняет установку с бэкапом. Установщик не запускается автоматически при сборке.

Первый live-playtest: Bedrock регистрация/Refresh/Exit, закрытие и `/auth`, подтверждение Telegram, неправильный/правильный пароль, тайм-аут, переподключение и отсутствие влияния старого окна на новый вход.
